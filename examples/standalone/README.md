# Standalone example

SDK example source for development and tests; it is not started with the platform.

[SDK integration](../../docs/integrate-sdk.md) · [Compose installation](../../docs/install-compose.md) · [Telemetry tests](../../tests/README.md)

## Run as a host process

Use Go 1.27.3 or newer and start the Compose platform first. This example has its
own `go.mod`, so enter its directory before running it:

```bash
# From the repository root
cd examples/standalone
export OTEL_EXPORTER_OTLP_CERTIFICATE="$(pwd)/../../compose/secrets/app/server-ca.crt"
export SIGNET_OTLP_API_KEY="$(cat ../../compose/secrets/app/token)"
OTEL_ENDPOINT=grpcs://localhost:4317 OTEL_ENVIRONMENT=compose LISTEN=127.0.0.1:18080 go run .
```

The default service name is `standalone-demo`, and the instance ID is the hostname.
Without `LISTEN`, the example binds to `:8000`; the command above uses port 18080
to avoid an existing service on 8000. Change the port if needed.

Metrics and traces are sent to the Agent. JSON logs go to stdout; the platform's
Docker filelog receiver does not collect host-process stdout automatically.

## Run in Docker for log collection

From the repository root, with the platform already running:

```bash
docker build -f examples/standalone/Dockerfile -t signet-standalone:local .
# Also fixes permissions for credentials generated by older script versions.
chmod 644 compose/secrets/app/server-ca.crt
docker run -d --rm --name signet-standalone-demo \
  --network signet_default \
  --log-driver json-file --log-opt max-size=10m --log-opt max-file=3 \
  -e OTEL_ENDPOINT=grpcs://otel-node-agent:4317 \
  -e OTEL_EXPORTER_OTLP_CERTIFICATE=/run/secrets/server-ca.crt \
  -e SIGNET_OTLP_API_KEY="$(cat compose/secrets/app/token)" \
  -v "$(pwd)/compose/secrets/app/server-ca.crt:/run/secrets/server-ca.crt:ro" \
  -e OTEL_ENVIRONMENT=compose \
  -p 127.0.0.1:18080:8000 \
  signet-standalone:local
```

Choose either host or Docker execution, or use different host ports. The Docker
command joins the existing platform network and lets Agent collect JSON stdout.
It does not add the example to the platform Compose file.

## Generate traffic and verify

Wait for the example to become ready, then generate requests:

```bash
curl -fsS http://127.0.0.1:18080/healthz
curl -fsS http://127.0.0.1:18080/readyz
for i in $(seq 1 10); do
  curl -sS 'http://127.0.0.1:18080/hello?name=Signet'
  curl -sS 'http://127.0.0.1:18080/work?delay_ms=250'
  curl -sS 'http://127.0.0.1:18080/error'
  sleep 1
done
```

`/hello` and `/work` return HTTP 200; `/error` intentionally returns HTTP 500 and
logs `example failure`. `/work` caps its delay at 2 seconds, so it cannot by itself
exercise the default 3-second slow-trace retention rule.

Wait 30–60 seconds, then follow [platform verification](../../docs/install-compose.md#verification).
Select namespace=`compose` and service=`standalone-demo` in Grafana. Check heartbeat
and request metrics, error traces, and, for Docker execution, correlated logs.
Ordinary traces are retained at 1%; error traces are the reliable verification case.

Stop a host process with Ctrl+C. Stop the container with:

```bash
docker stop signet-standalone-demo
```

The container is removed automatically; platform data remains. The separate
[SDK test stack](../../tests/README.md) provides automated telemetry assertions.

These examples always use TLS + Bearer authentication. Set `SIGNET_OTLP_API_KEY`
to the raw API key and `OTEL_EXPORTER_OTLP_CERTIFICATE` to a CA file path.
Startup code constructs `OTLPHeaders["Authorization"] = "Bearer " + token`.
The CA file is required. Go initialization uses `signet.Init(signet.Config{...})`
with explicit service, transport, authentication, metrics and tracing fields.
